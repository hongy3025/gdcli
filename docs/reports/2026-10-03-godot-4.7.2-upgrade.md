# Godot 4.7.1 → 4.7.2 升级核对

## 结论

- 本机 `D:\app\devel\Godot\v4.7.2\godot_console.exe --version` 实测输出：`4.7.2.stable.official.ed1daf0bf`。
- 4.7.2 是维护版本。官方发布公告称相对 4.7.1 **暂无已知不兼容**，并推荐升级；这不表示所有边界行为完全相同。
- 已更新测试工具的 Windows 默认路径，并让共享 E2E fixture 使用已有的 `resolve_godot_bin()`，解决其原先绕过默认路径、只从 PATH 查找 `godot` 的问题。
- [INFERENCE] 根据完整变更清单、实际调用边界及下述真实编辑器烟测，未发现本仓库必须进行 Godot API 适配的地方。保持 godot-rust `0.5.4` / `api-4-7`、`.gdextension` 的 `compatibility_minimum = 4.7` 和项目 `config/features` 中的 `4.7` 不变；继续支持 4.7.x，不把最低版本提高为 4.7.2。

## 与 gdcli / gdapi 的对应关系

以下“不需适配”是源码核对的结论，不是对所有用户项目行为的保证。

| 变更 | 仓库实际使用及判断 |
|---|---|
| [唯一主线程 / 生命周期](https://github.com/godotengine/godot/pull/121161) | `gdapi/rust/src/server.rs`、`queue.rs`、`process_runner.rs` 的后台工作传递原生字符串、字节和通道；Godot 类型转换在 `lib.rs` 包装层，路由由 `plugin.gd` 的 `_process` 分发。没有自行声明/转交引擎主线程的实现。[INFERENCE] 不需新增线程适配；已实测扩展与原生进程往返。 |
| [GDExtension 父类暴露](https://github.com/godotengine/godot/pull/120985) | `GdApiServer` 和 `GdApiProcessRunner` 直接继承公开的 `RefCounted`，没有隐藏扩展父类链。补丁修正引擎内部遍历，不改变注册接口签名。[INFERENCE] 不需更换 Rust API feature；两类均在真实编辑器中使用成功。 |
| [autoload 状态判断](https://github.com/godotengine/godot/pull/121509) | 引擎将复用判断改为 `is_inside_tree()`。本仓库 runtime probe 是游戏 autoload；已实测连续两轮 run → connected → stop，无需移除既有启动/停止逻辑。 |
| [TLS 熵源](https://github.com/godotengine/godot/pull/121759) | `runtime/services/network_service.gd` 使用 Godot `HTTPRequest`，HTTPS 直接使用引擎 TLS，未自定义熵源或禁用证书验证。已实测 HTTPS 请求成功。CLI 到 addon 的本地 HTTP、Rust TCP 服务与 LSP 不使用这条 TLS 路径。 |
| [create_temp 空 prefix](https://github.com/godotengine/godot/pull/121315) | 内置实现没有调用 `DirAccess.create_temp`；runtime 使用固定 `.godot/gdapi_runtime`，文件写入使用显式临时文件名。[INFERENCE] 不需适配。 |
| [rand_weighted 负权重](https://github.com/godotengine/godot/pull/120004) / [Color.hash](https://github.com/godotengine/godot/pull/121237) | 前者现在对负权重报错并返回 -1；后者修正绿色分量、可能改变哈希值。内置实现没有负权重采样调用，也不持久化 Color 哈希。[INFERENCE] 本仓库不需改动；用户项目若依赖这些行为，需自行核对。 |
| [Windows DispatcherQueue](https://github.com/godotengine/godot/pull/122261) / [网络盘访问](https://github.com/godotengine/godot/pull/121192) | 属于引擎平台实现修复，仓库无 WinRT 调用或网络盘标签假设。[INFERENCE] 不需仓库适配；本次 headless 烟测不证明 GUI dispatcher/高回报率鼠标路径已验证。 |
| LSP、HTTP、导出协议 | 完整清单没有 LSP 协议、HTTP 请求接口、桌面运行/停止接口或 export preset/命令 API 的迁移条目。类补全图标不等于 LSP 协议修复，Android 编辑器构建也不等于导出接口变更。已实连 LSP；不新增 patch 版本分支。 |

## 本次代码与文档修改

- `tests/e2e/m2/helpers.py`：Windows 默认二进制改为 4.7.2；其他平台继续使用 PATH 中的 `godot`。
- `tests/e2e/shared_fixture.py`：使用现有解析器，优先级为非空显式 `godot_bin` 参数 → `GODOT_BIN` 环境变量 → 平台默认值。
- `README.md`、`AGENTS.md`、当前待办中的验证命令更新为新路径；CHANGELOG 记录升级。
- 2026-07/08 的历史报告与当时的 headless 设计/计划保留 4.7.1，避免把原有验证证据改写为 4.7.2；`Cargo.lock` 中 `async-task` 的 4.7.1 是 crate 版本，与引擎无关，不修改。

## 已执行验证

### 升级前配置问题

在未设置 `GODOT_BIN` 的独立进程中调用原共享 `build_environment`，因 PATH 无 `godot` 而得到 `FileNotFoundError` / `Godot 4.7.x is required`。升级后同一默认调用实际使用新路径，版本检测返回 `(4, 7, 2)` 并成功启动编辑器。

### 真实程序烟测（临时项目，不新增永久测试）

使用共享 fixture 构建、安装 addon、复制原生库并启动真实 Windows headless 编辑器，观察并断言：

- `godot/version`、`gdapi/health/ping`、`project/info` 成功，版本为 4.7.2。
- `project/run` → `runtime/status` 为 `connected` 且 `editor_playing = true`；`project/stop` 后为 `stopped`、`pending = 0`、`editor_playing = false`。另一个临时会话连续两轮均成功；实际 runtime transport 为 `file`。
- `gdcli status` 的 gdapi 与 LSP 均已连接；`lsp capabilities`、`lsp symbols scripts/player.gd` 和 Godot 扩展 `lsp native-symbol RefCounted` 成功。
- `process/run` 调用真实 Python 子进程，退出码 0，stdout 保留字面参数 `a;b $(whoami)`，stderr 与预期一致。
- `network/http_request` 对 `https://example.com/` 使用正常证书验证，返回 HTTP 200、577 字节；解码后的正文长度与 SHA-256 均匹配响应。

两次烟测的行为断言全部通过，但初次即时删除临时目录时遇到 Windows `~gdapi.dll` 访问拒绝，导致烟测脚本当次退出码为 1。仅重试失败的目录清理步骤后均成功删除；没有重跑已成功的行为断言，也没有把脚本退出码记作 0。临时项目与脚本均未留在仓库。

### 格式与既有测试

- `python scripts/format-gd.py` / `python scripts/format-gd.py --check`：569 个 GDScript 文件通过，无文件发生修改。本次未修改 `.gd`，因此变更文件的 gdlint 范围为空。

## 导出模板注意

`D:\app\devel\Godot\v4.7.2\export_templates` 实际为空；检查的用户 Roaming/Local Godot 标准模板位置也未找到模板。此次未执行导出验收。使用 `export/run` 前应按 Godot 文档安装匹配的 **4.7.2** 导出模板，不能把旧 4.7.1 模板视为已升级。该环境准备项不要求修改本仓库导出接口。
