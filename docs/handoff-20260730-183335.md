## Working practices

### E2E test development: always `-x` first

When running E2E tests during development, **always pass `-x`** (`pytest -x`) to stop at the first failure. Most E2E failures during migration are timeouts or fixture setup errors — waiting for the full suite to finish only wastes wall time. The pattern is:

1. `pytest -x tests/e2e/m<N> -q --durations=10`
2. Diagnose and fix the failure
3. Repeat until the module passes cleanly
4. Only then run the full module without `-x` to confirm no latent failures

This replaces the implicit "run everything and debug the summary" approach.
